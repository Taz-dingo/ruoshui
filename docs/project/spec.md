# 项目 Spec

最后更新：`2026-07-10`

## 产品定义

`若水广场` 是一个以常州老校区为对象的 Web 数字纪念项目，通过空中 `SOG` 场景、地点和图文笔记，让校友重新看到并讲述那个地方。

它不是通用 3D 平台，也不是先做规模化社区；第一目标是低门槛、高质量、可控叙事的校园重访体验。

## 必须成立

- 在浏览器中稳定展示已验收的高质量空中场景。
- 让用户通过镜头、地图和场景热点理解校园空间。
- 让真实故事与空间点位双向关联：从场景看笔记，也能从笔记回到场景。
- 通过 Cloudflare 提供可上线的页面、API、关系数据和媒体存储。

## 当前范围

### 必须有

- 可发布、可分享的 Web 场景页。
- 桌面端稳定体验和基础移动端兼容。
- 加载、解析、错误和空状态反馈。
- 镜头预设、小地图和真实 3D 热点。
- 社区笔记 feed、详情、轻发布和多图能力。
- 帖子与场景点位双向关联。
- Cloudflare Pages、Workers、D1、R2 的可维护生产路径。

### 可选但不优先

- 背景音乐与更丰富的镜头过渡。
- 点赞、收藏和浏览计数。
- 轻量内容管理或显式种子工具。

### 明确延后

- 登录、权限、审核和开放式 UGC。
- 完整 CMS、视频投稿和小程序。
- 新一轮模型训练、算法切换或自研渲染器。

## 技术边界

- 前端：React + TypeScript + Vite + Zustand。
- 场景：PlayCanvas Engine API + SOG；正式模型由 R2 经同源 `/edge-models/*` 提供。
- 服务：Hono app core，通过依赖注入挂载 Workers/D1 主路径与 Node/PostgreSQL fallback。
- 媒体：R2；上传必须验证大小、类型、有效期和签名，并显式确认入库。
- 部署：Pages 发布前端壳；重量级模型从 R2 经 Pages Functions 同源代理提供。

正常页面加载只能读取业务数据，不得隐式创建 scene、pin 或帖子。初始化内容应通过显式种子或管理流程完成。

## 体验原则

- 场景是第一屏，UI 不压过纪念空间。
- 文案保持克制、温暖，不把页面做成技术 benchmark 面板。
- 点位内容必须有空间意义，避免脱离场景堆普通信息流。
- 首次访问优先稳定和可理解，再追求复杂动画或极限性能。
- 移动端控制必须尊重安全区、旋转和双指手势。

视觉与组件细节见 [`web-style-system.md`](web-style-system.md)。

## 上线成功标准

- 生产地址可稳定打开并加载正式场景。
- 桌面端核心浏览和点位流程无阻塞；移动端具备可用基础。
- 至少一组真实故事能走通“场景 → 笔记 → 社区/详情 → 场景”。
- API、模型和媒体资源失败时有明确兜底。
- 生产构建不把超限模型直接打进 Pages 静态产物。
