# 项目 Plan

最后更新：`2026-08-25`

本文件只维护**阶段结构**；具体执行顺序与 checklist 统一见 [`tasks.md`](tasks.md)。

## 已完成基础

- 已验收高质量 `SOG` 场景，并由 R2 经 `/edge-models/*` 提供。
- 已完成 React/Vite/PlayCanvas viewer、镜头、小地图、热点和基础加载反馈。
- 已上线 Cloudflare Pages，并建立 Workers + D1 + R2 的社区服务骨架。
- 已实现 feed / detail / compose / 多图 / 点位关联等基础能力，并跑通过本地技术闭环。
- 训练与算法实验历史已归档到 [`../archive/model-training/`](../archive/model-training/)。

## Phase 1：确定核心产品形态

目标：先确定用户最终如何在“空间 ↔ 地点故事”之间浏览，再继续扩展实现。

- 定义论坛 / 图文内容形态、地点故事内容模型和信息层级。
- 定义从 3D 点位进入内容、浏览内容、返回场景的完整交互。
- 定义点位点击后的镜头运动、最终停留状态和内容呈现方式。
- 明确 v1 发布边界，不让开放 UGC、登录和审核阻塞核心体验。

## Phase 2：建立内容生产链路

目标：让真实内容能够低摩擦地进入产品，而不是继续依赖测试数据。

- 建立真实点位体系和可视化点位 authoring 流程。
- 选定首批正式地点并定义内容标准。
- 对个人历史照片按地点筛选和整理。
- 跑通照片上传、D1 数据写入、R2 媒体、点位绑定、预览和发布。
- 使用显式 seed / 管理流程维护生产内容。

## Phase 3：收口场景与设备体验

目标：让已有核心体验在真实设备和真实场景边界下稳定成立。

- 处理 3DGS 模型边界，避免用户直接看到突兀空世界。
- 收口桌面端体验。
- 完成 iPhone Safari、Android Chrome、iPad / 触屏设备的核心链路验证。
- 根据真实设备数据再处理 GPU、内存和首屏成本。

## Phase 4：发布与验证

目标：达到可以直接发给校友使用的 v1。

- 完成 production 全链路 release acceptance。
- 覆盖慢网、模型 / API / 图片失败、点位跳转、内容浏览、返回场景和上传链路。
- 找少量真实校友做首次可用性测试，验证是否能理解空间、发现故事并形成记忆唤起。

## Phase 5：体验增强

以下能力不阻塞 v1：

- tiny preview → full SOG 或更进一步的 progressive loading。
- 更完整的 D1 / R2 生产化与媒体治理。
- 点赞、收藏、浏览计数。
- 登录、审核、开放投稿和完整 CMS。
- 新一轮模型训练、算法切换或自研 renderer。

只有当前业务目标明确要求时才重启这些方向。
